# 八项记忆任务方案：小苏打原任务与七项新设计

**2026-11-09，文档评审版。上一版八个任务的实现、YAML、BDDL 和专用测试已删除，代码仅保留原小苏打任务。** mb000 沿用用户原来的小苏打吊柜任务；mb001–007 为新设计，尚未实现或采样。此前的 40 个实例及物理检查属于[上一版实例准备](../../outputs/memory_bench_native_5/preparation_audit.json)，不能作为本版七项新设计的验证结果。

先选择有日常用途的活动，再确定历史信息如何影响 Query。遥操可达性用于筛选模型、尺寸和布局，不将任务预先限定为低处、桌面取放或收纳。本版保留食品取用、借阅、照明、餐具处理、刷洗、浇灌、通风和随容器搬运八种活动。

## 1. 八项任务概览

| 编号 | 记忆类别 | 日常活动与主要物体 | Key 做什么 | Query 做什么 |
|---|---|---|---|---|
| mb000 | L1 · Spatial Recall | 小苏打收纳后取用；小苏打盒、原厨房吊柜 | 将小苏打收入指定吊柜，关闭两柜 | 取出之前收好的小苏打，放到原柜下台面，关闭两柜 |
| mb001 | L1 · Spatial Recall | 借书后归还；一本书、两个书柜、阅读桌 | 从其中一个书柜取书到阅读桌备用 | 将这本书归还原来的书柜 |
| mb002 | L1 · State Recall | 暂停后恢复阅读照明；两盏台灯 | 离开阅读区前关灯，原先只有一盏亮着 | 重新打开原先使用的那盏灯，另一盏保持关闭 |
| mb003 | L1 · State Recall | 餐盘预冲后继续装洗碗机；两只盘、水槽、洗碗机 | 将两只需要预冲的盘冲净，记住哪只原先有食物残屑 | 仅将原先用过的盘装入洗碗机，备用盘留在机外 |
| mb004 | L2 · Memory Integration | 浴室刷洗与用品归位；海绵、清洁喷瓶、洗手池 | K₁ 取海绵到清洁处；K₂ 从另一组来源取清洁喷瓶 | 实际刷洗洗手池，再把两件用品分别还回各自原处 |
| mb005 | L2 · Memory Integration | 盆栽护理与归位；小盆栽、浇水壶 | K₁ 将盆栽移到护理处；K₂ 取来浇水壶 | 实际浇水，再把盆栽和浇水壶分别还回各自原处 |
| mb006 | L2 · Memory Updating | 风扇使用、暂停收放、再次通风；便携风扇 | K₁ 在临时使用位 A/B 开风扇；K₂ 关机并按新安排收放到 A/B | 从最新存放处取回风扇，放到固定书桌使用位并开启 |
| mb007 | L2 · Memory Updating | 水果装篮、整篮转移、取出备餐；苹果、两只野餐篮 | K₁ 把苹果放入其中一篮；K₂ 搬动两篮到出发准备位 | 根据苹果所在篮子的最新位置，取出苹果放到备餐盘 |

仅 mb000 使用吊柜，沿用原任务，不把其操作方式推广到其他七项。两项 ST 分别记忆电器的历史开关和餐具的历史使用状态；两项 MI 除记忆两个来源，还实际执行刷洗或浇水；两项 MU 分别追踪物体直接换位和物体随容器换位。

## 2. 保留的文档要求

1. **四类各两项。** SP/ST 属于 L1，各 `1K + 2I + Q`；MI/MU 属于 L2，各 `2K + 2I + Q`。Bridge 连接片段，Q 最后执行；MU 的 K₁ 必须先于 K₂。
2. **每个 Key 有独立活动结果。** 取书备读、离开前关灯、预冲餐盘、备齐清洁用品、准备盆栽护理、布置通风、暂停用电设备、打包和集中行李，都应在真实轨迹中发生。不以任意切段增加 Key 数，也不虚构已经阅读、用餐、擦洗或维修。
3. **K/Q 同房间。** 一个任务的全部 K/Q 位于同一个场景、同一个房间实例；两个 I 分别位于另外两个房间实例，操作对象、容器、支撑物及状态依赖与 K/Q 隔离。园艺任务的 K/Q 也必须留在同一 `garden_*` 实例，不能把跨房取水混进来。
4. **同一物体贯穿 K/Q。** 身份、模型和尺寸固定；不在阶段间换一个同款物体，也不重置物体、颗粒或容器内容。机器人按现有流程复位，物体世界连续继承。
5. **同一模板的 Q 指令固定。** 变体改变历史答案，不能改变 Q 的措辞、机器人起点分配或顺序来暗示答案。内部 A/B、角色绑定和答案不进入策略观测。
6. **MI 的两条信息独立。** 两物体来源分别二选一，覆盖四个组合，不能通过“一件占 A，所以另一件只能在 B”推导。K₁ 不提前暴露第二件来源，K₂ 不重述或展示第一件来源，检查全部相机、语言、动作和 Bridge。
7. **MU 保留真实更新。** mb006 保留 K₁ 使用位置与 K₂ 最新位置的独立组合，包含保留位置和换位置；mb007 保留“目标在篮中、篮子被移动、目标随之移动”的真实物理链。允许 K₂ 单独提供最新位置，不强求所有 MU 的两段都不可缺少。
8. **当前观测不能直接给答案。** 历史状态在 K 后应消失；来源归还任务不能留下空位标记；取回任务的 Q 起始视野不能直接看到目标。I/B 不能改变记忆对象或重新揭示答案。能搜索补救的任务，最终成功与首次正确选择分开分析。
9. **实现优先使用原生能力。** 先调整模型、尺寸、支撑物、遮挡、路线及任务规模。保持既有 BDDL 条件与对象读写声明，不为某个任务添加专用放置区域、角度、状态修补或内容物固定函数。

本轮交付是设计文档。后续实施仍先验证设计，再用 `memory_bench/scripts/prepare_session.sh` 每项采样 5 个最终实例；新选 I 要下载该任务的全量录制，5 不限制 I 下载量。长期正式数据规模和序列要求沿用[总体设计](benchmark_design.md)。

## 4. 具体设计

### mb000 · 原小苏打吊柜任务

**按原任务保留，不重新发明流程。** 对应 [retrieve_baking_soda_from_top_cabinet.py](../tasks/retrieve_baking_soda_from_top_cabinet.py)，场景为 `house_double_floor_lower / kitchen_0`，使用 `box_of_baking_soda/pskrgy`、`top_cabinet_tynnnw_0/1` 和柜下 `bar_egwapq_0`。

- **K：** 将柜下台面的小苏打放入本实例指定的吊柜，关闭两柜。原 Key 用距离客厅远近指明柜子。
- **Q 固定指令：** “取出你之前收好的小苏打，放在吊柜下方的厨房台面上，并关好两个柜门。”
- **变体和判定：** 藏在柜 A/B；原生 `inside`、`ontop`、`not open`。Q 不提示柜子。
- **记忆边界：** 关门后遮住盒子；允许搜索，但错误开柜与首次选柜正确性须与最终取回成功区分。

本版仅将它列为 mb000，不改原模块、配置或已有数据。

### mb001 · 借书后归还原书柜

**活动：** 客厅借书到阅读桌，稍后归还。候选为上层 `living_room_0`，使用已存在的 `bookcase_otwukr_0/3` 与 `desk_iotfzl_0`；新增一本硬皮书，优先考察 `hardback/acbrnv`（约 22.3 × 17.2 × 3.1 cm）。

- **K：** 从书柜取出这本书，放到阅读桌备用；书的来源为 A/B。
- **Q 固定指令：** “把刚才借到阅读桌上的书归还原来的书柜。”
- **记忆：** 书的历史来源。K 结束书在同一阅读桌，桌上落点和姿态的分配与来源独立，两个书柜不留差异化空位或标记。
- **判定：** 同一书回到正确书柜的可用层板；采用原生支撑/包含关系，不指定柜顶、层号、书脊朝向或精确插缝。
- **待核验：** 书厚与夹爪、层板前缘净空、柜内 `inside`/`ontop` 对实际支撑面的表达，以及 Q 入口是否有来源痕迹。没有执行阅读的轨迹不标注为“读完书”。

### mb002 · 暂停后恢复阅读照明

**活动：** 临时离开阅读区前关灯，回来继续使用原来的阅读位。优先使用单层 `bedroom_0` 已有的 `table_lamp_qgdwbh_0/1`；两灯模型元数据具有发光与开关部位，约高 55 cm。

- **初态：** 两灯位置固定，恰好一盏亮；A/B 独立于床头位置和模型身份。床头用品不能随答案改变。
- **K：** “先关好阅读区的灯，稍后回来继续。”出口两灯均关闭。
- **Q 固定指令：** “恢复刚才的阅读照明，只打开之前使用的那盏台灯。”
- **记忆与判定：** 历史 `toggled_on` 对象；Q 要求历史灯开、另一灯关，不能全打开绕过选择。
- **待核验：** 首个 Key 中能直接看见亮/灭差异；实际接触开关可达；关闭后无余亮、开关姿态或其他可见状态泄露答案。任务目的就是恢复照明，不添加无用搬书来凑动作。

### mb003 · 餐盘预冲后，继续装入用过的餐盘

**活动：** 餐后先处理表面残留，之后把用过的盘送入洗碗机。两只餐盘都因敞放有浮尘，其中只有一只还有食物残屑、代表已使用；另一只是待冲净的备用盘。用过的是 A 还是 B 为历史状态变体。

候选在下层 `kitchen_0`，已有 `drop_in_sink_lkklqs_0` 和 `dishwasher_ynrhuk_0`。两盘用不同但尺寸接近的现有模型，例如 `plate/aewthq`、`plate/akfjxx`，历史使用状态与外观独立。能力依据为原生 [rinsing_dishes](../../bddl3/bddl/activity_definitions/rinsing_dishes/problem0.bddl) 的去残屑及装洗碗机流程。

- **K：** 两盘均做真实预冲，去掉浮尘与食物残屑，暂放到共同等待处；清理顺序、放回规则均与历史使用状态独立。出口两盘当前都没有残屑。
- **Q 固定指令：** “继续处理这次用过的餐盘：把预冲前有食物残屑的那只装入洗碗机，备用盘留在外面。”
- **记忆：** 某盘过去是否有 `covered(breadcrumb)`，不是现在是否脏、哪只更湿或哪只离洗碗机近。
- **核心判定：** 历史用过盘 `inside dishwasher`，备用盘不在机内。关门作为自然收尾候选；能否追加启动，须核验本地模型的门、按钮和实际操作后再冻结，原参考 BDDL 本身只要求去残屑与装机。不宣称已完成洗涤循环或消毒。
- **待核验：** 实际冲洗能清除指定物质；两盘的水迹、颗粒残余、落点、朝向与动作次序不编码答案；盘沿抓取、机器门和内部空间可操作。若无法消除当前可见线索，本版 ST 不成立，须重设预处理流程，不能在后台抹掉水迹或状态。

### mb004 · 刷洗洗手池后，将两件用品各归原处

**活动：** 浴室清洁准备、实际刷洗和用品归位。候选为下层 `bathroom_0` 的 `drop_in_sink_hecjnt_0`，新增 `sponge/aewrov`（约 10.5 × 7.0 × 2.1 cm）和 `detergent_atomizer/rhfpsb`（约高 25.6 cm）。喷瓶元数据包含开关和颗粒施加部位。

- **K₁：** 从 A₁/A₂ 之一取海绵到清洁准备处，提供海绵原位置。
- **K₂：** 从独立的 B₁/B₂ 之一取清洁喷瓶到准备处，提供喷瓶原位置；海绵保持在准备处。
- **Q 固定指令：** “用备好的用品刷净洗手池，然后把海绵和清洁喷瓶分别放回各自原来的位置。”
- **记忆与变体：** 两个来源独立，四个组合。两条归还绑定都要正确，实际清洁不能替代记忆归位的检查。
- **真实交互：** 清洁剂使海绵达到原生清洁条件，再接触擦除 `stain`；目标为 `not covered(sink, stain)`。喷瓶停喷后归位。不能只把海绵移到水槽旁就算完成刷洗。
- **待核验：** 两组来源须由真实支撑物、遮挡和接近方向隔离，不用同一台面坐标区补丁；K₁ 全相机看不到喷瓶来源，K₂ 不再暴露海绵来源；喷洒可控、海绵可夹持、池面可触达。能力参数明确去污渍需要相应清洁液浸润，不能把蘸水当成万能清洁条件。

### mb005 · 浇花后还原盆栽与浇水壶

**活动：** 把一盆植物移到便于浇灌的护理处，取水壶浇水，结束后恢复摆放。候选在单层 `garden_0`，所有 K/Q 留在该园艺房间实例。小盆栽候选 `pot_plant/cvthyv`（约 17 × 17 × 21 cm），水壶候选 `watering_can/pewtns`。

- **K₁：** 从花架 A₁/A₂ 之一把盆栽移到护理处，提供植物原位置。无需模拟修枝或换土。
- **K₂：** 从另一个方向的工具位 B₁/B₂ 之一取来浇水壶，提供壶的原位置。按原生水源机制在初态准备好用水，不另加跨房补水；原浇花活动的跨房流程不能直接照搬。
- **Q 固定指令：** “给准备好的盆栽浇水，再把盆栽和浇水壶分别放回原来的位置。”
- **记忆与变体：** 两来源独立，四个组合。不能由盆栽的种类、壶的外观或“空出来的花架”推导来源；两个来源组都有同等可用空间。
- **真实交互与判定：** 沿用 `watering_indoor_flowers` / `watering_outdoor_plants` 的浇灌能力，执行实际出水，原生完成条件为 `covered(plant, water)`，再检查两项归位和水源关闭。不宣称模拟了土壤含水量或植物生长。
- **待核验：** K₁/K₂ 信息隔离、浇水方向、颗粒保留和支撑稳定性。壶的原模型约 90 × 31 × 50 cm，不能直接称为轻便小壶；应先检查把手、质量和合理家用尺寸下的出水能力。尺寸、两个花架及两个工具支撑物尚未冻结。

### mb006 · 风扇换了暂存处，继续使用时找最新位置

**活动：** 先在临时使用处通风，离开前关机收放，稍后在书桌继续使用。候选为卧室/书房中的一个房间，使用 `electric_fan/lclkju`（约 30 × 41 × 53 cm，有原生开关部位）。房间需有两处既可临时使用也可暂存的支撑物 A/B，以及固定书桌使用位 C；具体房间实例待核验。

- **初态：** 风扇在 C 且关闭；初态不随记忆变体改变。
- **K₁：** 把风扇搬到指定的临时使用处 A/B 并打开，完成通风准备。出口位置 A/B 是第一条位置记忆。
- **K₂：** “暂停通风，关掉风扇，并按新的安排收放到指定位置。”最新位置独立选择 A/B；如果已在该位置，只需关机并保留，不为凑动作强行搬走再搬回。
- **Q 固定指令：** “继续在书桌使用风扇，把刚才收好的风扇取到书桌并打开。”
- **变体：** K₁ 出口 A/B × K₂ 出口 A/B，共 A→A、A→B、B→A、B→B 四种。换位组检测更新，原位组检测保留；两组 K₂ 都有真实的关机暂停操作，动作成本可以不同。
- **判定：** K₁ 在对应使用处且开；K₂ 在最新存放处且关；Q 到 C 且开。另需由轨迹分析首次接近的是最新位置还是旧位置，不能只看最终成功就宣称记忆更新正确。
- **待核验：** 两暂存点从共用 Q 起点均不可直接看见目标，I/B 不重新提示；这需要真实家具遮挡和路线，而非禁看规则。风扇实际可抓、转动部件不干涉、开关可操作。只使用开/关，不虚构档位、摆头角或风速判据。

### mb007 · 苹果装进篮子后，跟踪整篮的最新位置

**活动：** 准备野餐，先装水果，再把篮子集中到出发准备处；随后取出苹果放到备餐盘备用。K/Q 全在同一厨房/餐厅房间实例，不搬到另一房间的玄关。

候选物体为一个 `apple/agveuv`（约 8.7 × 7.4 × 7.4 cm）、两只模型不同的 `wicker_basket/dgkhyn` 与 `wicker_basket/jqfftz`、固定备餐盘。篮子原模型约 26 × 41 × 19 cm、31 × 31 × 28 cm；两者都必须能容纳同一苹果，外观不能固定预测哪篮装苹果。

- **K₁：** 把苹果放入指令指定的篮 A/B，另一篮不放苹果，完成水果打包。篮子此时留在打包支撑物上。
- **K₂：** 将两只篮子搬到本房间的两个出发准备位 C/D。摆放排列独立分配为 A→C、B→D 或 A→D、B→C；指令只指定篮子身份与家具参照，不报出苹果在哪篮，搬运先后也与苹果所在篮独立。
- **Q 固定指令：** “取出刚才装进野餐篮的苹果，放到备餐盘上备用。”
- **记忆与变体：** 苹果→篮子 A/B × 两篮的最终排列，共四种。K₁ 建立包含关系，K₂ 更新容器位置，Q 找到目标篮的最新地址。K₂ 中只抓篮子，不直接搬苹果。
- **判定：** K₁ 苹果在选中篮中；K₂ 两篮到对应支撑物且苹果仍在同一篮内；Q 同一苹果到备餐盘。容器与内容物都列入 K₂ 写集合，不能焊接、瞬移或在后续阶段重新填篮。
- **待核验：** 两篮都容易抓，轻载搬运不翻倒，苹果不滚出；Q 起点不直接看见苹果。若 K₂ 相机再次看到苹果，要记录为再次提供的目标证据，不能宣称这一实例完全依靠隐藏包含关系推理。该任务允许开视野后搜索，须另记首次找篮是否正确。

## 5. 场景、I 和实现可行性的后续核验

本版不会为了沿用已下载 I，把所有任务重新搬回厨房。先保持活动语义与房间要求，再选同场景另外两个房间的完整 I。小苏打原任务可沿用 `turning_on_radio` / `putting_shoes_on_rack`；其余新方案的 I 不在本轮冻结。已有全量素材可复用，但仍需核对房间、物体、物质系统及真实轨迹中的隔离。

本版涉及清洗和浇灌，除刚体外还有水、残屑、污渍和清洁剂。原生 BEHAVIOR 提供这些交互，但现有 Memory Bench 的最终场景组装仍有按普通物体查询 `init_info` 的路径：系统绑定不能直接当成普通物体资产。因此 **mb003–005 还有通用系统组装与状态继承的接入问题，尚不能声称直接可跑**。后续应先核验现有系统处理通路和必要通用辅助逻辑的范围，不通过改状态比较、跳过系统、任务专用补丁或隐藏重置来放行；本轮不修改这些代码。

实施时逐项验收：

1. 先确认活动、历史事实、变体及 Q 是否符合本版目的；模型或布局失败时换同用途物体/场景，保留记忆类型和真实活动。
2. 核对同房间 K/Q、两个完整单房间 I、物体与系统隔离、固定身份和当前框架可表达性。新增相同类别物体选不同模型，或使用真实场景已有的独立实例，遵守现有共享绑定规则。
3. 检查每个变体的初态、Key 后态、下一阶段入口及 Q 目标，使用原生物理与判据；清洗/出水还要验证实际交互，不能仅手动设目标状态。
4. 按头部和双腕相机审查历史证据、MI 信息独立性、当前状态泄漏和 I/B 重曝；涉及搜索的任务区分首次选择和最终成功。
5. 设计通过后，再运行原准备脚本各生成 5 个最终实例，分别记录准备通过、实际遥操通过和完整序列通过。旧版检查结果不继承为本版验收。

如果某项难以成立，应在同类日常活动中重新设计并更新本文件，说明保留和改变了哪些要求。不能只为了凑齐八项和通过采样，再退回重复的手电筒、吊柜和取放任务。
