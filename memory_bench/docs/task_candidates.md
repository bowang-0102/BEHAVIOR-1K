# Memory Bench：8 个任务的设计与资产依据

保留四类、每类两个任务。**本版优先使用上下层住宅：上层 3 项、下层 2 项、单层 3 项。** 单层只保留依赖现成低柜的状态、咖啡整合和嵌套搬运任务；不再为单层厨房安排三种记忆任务。上下层是两个独立场景，不需要跨楼层导航。

**核验范围：** 已核对本地 stable 场景、家具房间、物体类别与模型文件，并实现配置、BDDL 和变体条件。抓放、开合、容器净空、相机遮挡和实际导航尚未通过仿真验收；当前环境无法连接 NVIDIA 驱动。以下是待试操的实现方案，不代表可直接批量采集。

## 1. 八项任务

配置文件使用 `mb000`–`mb007`；BDDL 仍用 `mb_xxx`，Python 模块名不带 `mb`。

| 编号 | 类别 | 场景 / memory room | 日常活动 | Key → Query |
|---|---|---|---|---|
| mb000 / SP1 | Spatial Recall · 空间记忆检索 | 上层 / `bedroom_2` | 收好备用手电筒，稍后取用 | 收入书桌上的指定工具箱并合盖 → 取出手电筒放回桌面 |
| mb001 / SP2 | Spatial Recall · 空间记忆检索 | 上层 / `living_room_0` | 借用客厅饮具后归位 | 从矮书柜顶拿杯子到书桌 → 归还原柜顶 |
| mb002 / ST1 | State Recall · 状态记忆检索 | 单层 / `utility_room_0` | 暂停后继续工具收纳 | 关上原来打开的柜门 → 将手电筒收入原来打开的柜子 |
| mb003 / ST2 | State Recall · 状态记忆检索 | 下层 / `kitchen_0` | 在早餐桌暂停后继续打包家用工具 | 合上原来打开的工具箱 → 将电钻装进该箱并合盖 |
| mb004 / MI1 | Memory Integration · 多片段记忆整合 | 单层 / `kitchen_0` | 准备咖啡用品，结束后归位 | 分别取杯子、糖罐到准备区 → 各自放回原台面、原柜 |
| mb005 / MI2 | Memory Integration · 多片段记忆整合 | 上层 / `living_room_0` | 准备茶歇用品，结束后归位 | 分别取杯子、糖罐到书桌 → 各自放回原柜顶 |
| mb006 / MU1 | Memory Updating · 动态记忆更新 | 下层 / `kitchen_0` | 饮具取用、收起、再次取用 | 杯子从台面到早餐桌，再收到一处台面 → 从最新位置取回 |
| mb007 / MU2 | Memory Updating · 动态记忆更新 | 单层 / `utility_room_0` | 工具装盒、整盒收纳、再次取用 | 手电筒装入小纸盒，再整盒入柜 → 取盒后拿出手电筒 |

K/Q 只记录准备、暂存和收纳，不假装执行了饮用、维修或清洗。动作不涉及叠放、启动电钻、倒糖或搬动满工具箱。

## 2. 片段和变体

- L1：**1K + 2I + Q**；L2：**2K + 2I + Q**。顺序在 config 给出，Q 最后执行；所有 K/Q 在同一房间。
- 两个 I 位于另外两个不同房间，只接受**完整官方单房间活动**。不支持 `subtask`、任意切段或局部目标；I 和 Bridge 不承担通行门开关。
- 变体只改变被测的位置或历史状态。目标物体、活动目的和 Q 指令固定；片段顺序独立分配。

| 类别 | 变体 | 150 实例的分配 |
|---|---|---|
| SP | 隐藏位置或原收纳位二选一 | 各 75 |
| ST | 初始打开的是两个容器中的哪一个 | 各 75 |
| MI | 杯子来源二选一 × 糖罐来源二选一，互相独立 | 四组合 38/38/37/37；准确数量读取分配文件 |
| MU1 | 起始台面二选一 × 最终台面二选一，中间早餐桌固定 | 换位置、回原位均覆盖；两端边际各 75 |
| MU2 | 装盒区域左/右 × 最终收纳柜二选一 | 38/37/37/38；两维边际各 75 |

不足 150 个实例时按权重分配实际已有实例，不宣称每个小批次都完全均衡。内部 A/B 和资产 ID 不出现在 Q 指令中。

## 3. 具体任务

### mb000 · 收好手电筒，稍后取用

上层卧室 2 的 `desk_uqcmzf_0` 上新增两只同款工具箱和一只手电筒。两箱在独立区域内固定摆放，用距卧室门的远近区分，避免“指定物体”没有可观察参照。

- **K：** 把桌上的手电筒放进指令指定的工具箱，合上两个箱盖；不搬箱。
- **Q：** “把之前收好的手电筒取出来，放在卧室书桌空位上，并合好两个箱盖。”
- **变体：** 收进远门箱或近门箱；Q 和取回区域不变。
- **判定：** K 要求手电筒在目标箱内、两箱关闭且仍在原区域；Q 要求手电筒回到桌面、两箱关闭。
- **验收重点：** 两箱占地、开盖扫掠、书桌实际支撑面及关闭后的视觉遮挡。箱子是新增资产，不声称原卧室已有两只工具箱。书桌约 1.60 × 1.60 m 的包围盒不等于整块平面都能摆放。

仍保留“Key 把物体藏起来，Query 取回”的 SP 形式。可通过打开两个箱子搜索补救，因此应另报首次选箱和额外开箱次数；当前代码只实现阶段完成条件。

### mb001 · 借出杯子，归还原位

上层客厅只有一只任务杯。原位为 `bookcase_otwukr_0` 或 `bookcase_otwukr_3` 的顶面，借用位置为 `desk_iotfzl_0`。

- **K：** 将柜顶杯子拿到书桌备用。
- **Q：** 将借出的这只杯子归还原来的矮书柜顶。
- **变体：** 原柜顶二选一；K 结束时杯子在同一书桌区域。
- **判定：** 正确书柜且确实在顶面；放进内部层板不算成功。书桌落点避开已有台灯。

### mb002 · 记住原来打开的柜子，继续收纳

单层工具间现有两只低柜，手电筒固定在工作台。初始一柜打开、一柜关闭。

- **K：** 暂停整理，关上打开的柜门；手电筒留在工作台。
- **Q：** 将手电筒放进开始整理时开着的柜子，关好两柜。
- **变体：** 初始开柜对象二选一，不改变手电筒的位置或柜内容量。
- **判定：** 正确柜内收纳且两柜关闭；不是只把历史柜门重新打开。

### mb003 · 记住原来打开的工具箱，继续装箱

改用下层厨房的 `breakfast_table_xftrki_0` 作为家用工具打包临时桌。两只同款工具箱摆在桌面两端，电钻在中间独立抓取区；初始只有一个箱盖打开。

- **K：** 暂停打包，合上打开的箱盖，电钻留在桌面。
- **Q：** 将电钻装进暂停前开着的工具箱，并合好两个箱盖。
- **变体：** 初始开箱对象二选一；两箱和电钻的区域不随答案变化。
- **判定：** 电钻在正确箱内、两箱关闭且未搬离各自区域。
- **验收重点：** 桌面约 0.93 × 1.49 m，两个箱子原模型约 0.26 × 0.61 m；必须实际检查两箱方向、盖扫掠和中间抓取区，不能只按面积判定可用。

### mb004 · 两次备齐咖啡用品，再分别归位

保留单层厨房，原因是其现有低柜能遮住糖罐，避免为了缩短导航改用高吊柜。

- **K₁：** 将杯子从两个原台面之一拿到咖啡准备区；糖罐仍在关闭的低柜中。
- **K₂：** 从指定低柜取糖罐到同一准备区，关门；不移动杯子、不重述杯子来源。
- **Q：** 杯子回原台面，糖罐回原柜，两柜关闭。
- **变体：** 杯子原台面 × 糖罐原柜，四个独立组合。
- **判定：** 两条原位置绑定都正确；Q 入口的杯子和糖罐使用与答案无关的分离区域。

必须审计所有相机、指令及 Bridge，确保 K₁ 没看到糖罐来源，K₂ 没再次给出杯子来源。仅完成两次取物不能证明需要两个 Key。

### mb005 · 两次备齐茶歇用品，再分别归位

上层客厅两组矮书柜顶分别提供杯子和糖罐来源；两件物体都被拿到书桌。

- **K₁：** 杯子从 `bookcase_otwukr_0/3` 之一到书桌。
- **K₂：** 糖罐从 `bookcase_otwukr_1/2` 之一到书桌，杯子保持不动。
- **Q：** 两件用品分别回到各自原来的柜顶。
- **变体：** 杯子原柜 × 糖罐原柜，四个独立组合。
- **判定：** 两个柜顶都正确；书桌摆放区域避开台灯并与答案无关。

**开放柜顶存在信息泄漏风险。** K₁ 如果已经看到了糖罐来源，就不能按两个必要 Key 验收；需要通过实际接近方向、相机视野和遮挡检查决定是否可采集，不能仅靠文字规定。

### mb006 · 杯子多次移动后，从最新位置取回

改用下层厨房两处操作台和早餐桌，省去高处取放和开柜操作。

- **K₁：** 把操作台上的唯一任务杯拿到早餐桌备用。
- **K₂：** 腾出早餐桌，将杯子收回指令指定的操作台。
- **Q：** “把最近收好的杯子拿回早餐桌备用。”
- **位置：** 横向台 `bar_byvbuc_0`、沿墙台 `bar_egwapq_0`；中间和 Q 目的地均为 `breakfast_table_xftrki_0`。
- **变体：** 横向台→早餐桌→沿墙台、反向换台，以及两种回原台对照。
- **判定：** 阶段位置依次成立，Q 杯子到早餐桌。另需从轨迹报告首次接近的台面是否为最新位置、是否误用旧位置。

此项考察同一物体的连续位置更新，**不要求 K₁、K₂ 都是不可替代信息**；K₂ 单独足以给出最新位置。Q 开始不能直接看到杯子的最终位置，I/Bridge 也不能重新提示。开放台面必须做全相机观测审计；如共用机器人起点直接看见杯子，本布局不能作为记忆任务验收。保留旧位置、仅 K₂、无记忆等对照，不能把普通可见取杯任务算作记忆更新。

### mb007 · 装入纸盒，随盒入柜，再次取用

单层工具间固定一只小纸盒和一只手电筒。

- **K₁：** 把手电筒平放进工作台上的纸盒，纸盒不搬离该装盒区域。
- **K₂：** 连同盒内手电筒搬动整盒，收入指定低柜，关好两柜。
- **Q：** 找到装有手电筒的盒子，先把盒子取到工作台，再拿出手电筒，关好柜门。
- **变体：** 盒子开始在工作台左/右区域 × 最后收入两柜之一。Q 的盒子和手电筒区域固定，不随答案改变。
- **判定：** K₂ 同时要求“手电筒在盒内”和“盒在正确柜内”；Q 两者分别在工作台的指定区域。

这与 mb006 的直接移动不同：目标与容器的包含关系保留，容器位置更新。K₂ 的写集合包含盒子和手电筒，回放两者真实状态，不假设只更新盒子就能自动带动物体。物理搬运不将手电筒焊接到盒子；掉落即不满足条件。

纸盒没有可开合盖，不设计合盖或拆盖。盒沿抓取、内壁净空、手电筒滚动和带载稳定性必须试操；K₂ 还需检查是否重新直接展示了手电筒。

## 6. 实现和验收

实现说明见 [eight_tasks_implementation.md](eight_tasks_implementation.md)。新增逻辑仅用于：固定家具绑定、同款双工具箱身份、变体初态，以及顶面/区域检查。K₁→K₂→Q 继续继承真实世界，不在阶段之间重置物体。MU2 的嵌套关系直接使用已有 BDDL 谓词和写集合。

批量采集前必须完成三件事：

1. **省力试操：** 检查每种变体的抓放、开合、浅层落点和带载搬运，记录重抓、掉落、碰撞与人工救场。摆不下或难操作就改布局，不能按外尺寸宣布通过。
2. **信息审计：** 全部相机、指令、I/Bridge 不泄露答案；MI 两段信息互补，MU 报告最新位置及旧位置干扰。开放来源的 mb005、开放目标的 mb006 尤其需要检查。
3. **完整序列：** I 目标、真实末状态、空手停稳、门状态、导航碰撞和完整回放都通过。分别报告记忆选择与动作成功，避免把搜索补救混同为记住。

同源 K/Q、反事实变体及仅 I 顺序不同的序列应成组划分训练/测试。当前没有新增首选位置、搜索次数等策略评价器，也未完成动态验收。
