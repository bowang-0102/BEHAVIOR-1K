# Memory Bench 长任务遥操采集说明

本说明适用于 `memory_bench/scripts/collect.sh` 启动的采集模式。同一实例的多个 Key 和 Query 在连续世界中依次采集，每个子任务独立保存 HDF5；每个子任务内可以保存检查点、回滚和暂停。切换子任务由两个独立按键完成。普通 JoyLo 模式保留原来的手电筒按键。

## 大任务和子任务的边界

- **大任务**：当前 `INSTANCE_ID` 的全部 Key 和 Query。一轮尝试对应一个 `attempt_NNNN/` 目录。
- **子任务**：一个 Key 或 Query。检查点只属于当前子任务；完成并切换后，不能回滚到上一子任务。
- **子任务切换**：校验当前出口，先保存并关闭当前子任务的 HDF5，再只恢复机器人到下一子任务的公共起点，保留物体状态和前序任务成果。恢复过程和等待开始均不写入任何子任务。
- **整轮重开**：保存当前尝试，再恢复同一实例的完整初始场景，从第一个 Key 重新采集；物体状态也会恢复。

## 按键表

键盘操作需要先让 OmniGibson 窗口获得焦点。手柄的左、右方向键指左 JoyCon 上原来控制两盏手电筒的按键。

| 按键 | 功能 | 作用范围 |
|---|---|---|
| JoyCon **左方向键** | 请求完成当前子任务；检查通过后独立保存 HDF5，恢复下一子任务的机器人起点，并停下来等待开始 | 子任务边界 |
| JoyCon **右方向键** | 开始已准备好的子任务；暂停或回滚后，也可以恢复当前子任务 | 当前子任务 |
| JoyCon **X** | 正在遥操时保存检查点；暂停时开始或恢复；已用 Y 选中检查点时执行回滚 | 当前子任务 |
| JoyCon **Y** | 循环选择当前子任务内的检查点，随后按 JoyCon X 执行回滚 | 当前子任务 |
| 键盘 **X** | 开始或恢复遥操，等待 GELLO 与机器人状态同步；不负责结束子任务 | 当前待采或暂停的子任务 |
| 键盘 **P** | 暂停，也会取消正在等待的开始同步 | 当前子任务 |
| 键盘 **R** | 保存当前尝试并重开整个大任务，仍使用同一个 `INSTANCE_ID` | 整个大任务 |
| JoyCon **Home** | 沿用原来的冷却限制；冷却结束后，保存并重开整个大任务 | 整个大任务 |
| 键盘 **Esc** / JoyCon **Capture** | 保存已有录制并退出；未完成整轮时，标记为中止 | 整个大任务 |
| JoyCon **B** | 切换视角 | 显示 |
| JoyCon **A** | 隐藏或显示无关物体，并切换任务相关物体的高亮提示；相关物体覆盖本轮 Key 和 Query 的绑定对象 | 显示 |
| 摇杆、上下方向键、ZL/ZR、L/R、减号/加号 | 保留原来的底盘、躯干、夹爪和锁臂控制 | 遥操 |

`N` 不再用于任务推进。在此采集模式中，左右方向键不再切换手电筒；普通 JoyLo 模式仍使用原来的手电筒映射。

## 一轮采集流程

1. 在 `memory_bench/scripts/common.sh` 配置场景和 session，在 `collect.sh` 设置实例、显示器和认证文件。分别启动服务端和硬件客户端：

   ```bash
   bash memory_bench/scripts/collect.sh
   # 另一个终端
   bash memory_bench/scripts/run_joylo.sh
   ```

2. 等待完整场景加载，机器人恢复公共起点并停稳。按 **右方向键**或键盘 **X**，等待 GELLO 与机器人同步，再开始遥操。
3. 长子任务中可以按 JoyCon **X** 保存检查点。需要重试时，按 **Y** 选择检查点，再按 JoyCon **X** 回滚。回滚后保持暂停，再按右方向键或 X 同步并继续。
4. 子任务完成后放下手中物体，让机器人停稳，按 **左方向键**。系统检查任务完成条件、空手、稳定和碰撞状态；不满足时提示原因，继续操作后可以重试。
5. 检查通过后，系统保存出口快照，将当前文件写完、刷新到磁盘并关闭，再恢复下一子任务的机器人起点。保存失败时保留缓冲和当前世界，保持暂停；按左方向键重试。此时不会自动开始下一段；按 **右方向键**或 X 确认开始。
6. 最后一个 Query 完成后按左方向键。检查通过并保存 Query 后，整轮尝试标为完成并退出。

左右方向键同时按下时，只处理结束请求；下一子任务仍需单独按开始键确认。

## 回滚的范围和记录

每个子任务开始时自动保存一个入口检查点。手动检查点和 JoyLo 配置启用的自动检查点都保留。切换到下一子任务时清空上一段的检查点，所以 `Y → X` 只能回到当前子任务内的位置。

回滚同时恢复机器人和物体的世界状态，并从正式轨迹中移除该检查点之后的动作。被移除的尝试保存在当前子任务 HDF5 的 `data/demo_0/rollbacks` 分支中；统一后处理只使用正式轨迹，不将失败分支导入训练序列。已完成子任务的文件保持不变。

Query 的柜门事件也随回滚撤销。例如，误开柜门后回到误操作之前的检查点，可以重新尝试；如果选中的检查点已经包含误操作，该违规仍然保留。

任务中途暂停或回滚时允许继续抓着物体。恢复时要求底盘/躯干输入回中、手臂与 GELLO 同步；躯干和夹爪继续暂停前尚未完成的目标，不会因为物理动作被暂停而永久等待到位。新子任务入口仍要求空手并对齐起点；出口仍要求空手、稳定、无碰撞。

## R 重开和 Esc 退出

**R 是整轮重开。** 它不会跳过子任务，也不会自动切到下一个实例。已完成子任务的文件保留，当前未完成段保存为 `<segment>_aborted.hdf5`，该轮 `attempt.json` 标为 `aborted`。随后恢复同一实例的初始世界，建立新的尝试目录，从第一个 Key 等待开始。

**Esc 是保存退出。** 它保留已完成文件和当前未完成段，但不会将未完成的子任务或大任务强行判为成功。后处理只接受包含全部 Key 和 Query 的完整尝试，不能把不同尝试的文件拼成一轮。

默认输出位于 session 的 `paths.output_root` 下：

```text
recordings/<session_id>/
└── instance_0001/
    ├── attempt_0001/           # 例如第一次尝试被 R 重开
    │   ├── attempt.json        # status: aborted；已有文件继续保留
    │   └── key_1_aborted.hdf5
    └── attempt_0002/
        ├── attempt.json        # status: complete 后可进入统一处理
        ├── key_1.hdf5          # 每个文件只有 data/demo_0，局部动作区间 [0,N)
        ├── key_1_entry.json
        ├── key_1_exit.json
        ├── query.hdf5
        ├── query_entry.json
        └── query_exit.json
```

重新启动同一个实例或按 R，都会选择递增的尝试编号，不覆盖旧文件。多 Key 会额外产生 `key_2.hdf5` 等文件。需要自定义目录时使用 `--session-recording-dir`；默认处理按上述标准目录寻找实例。

新流程不生成 `marks.json` 或 `marks.yaml`。`attempt.json` 记录整轮完成状态、TRO 身份及哈希、各独立文件和入口/出口快照、转场检查结果；它不再承担从长录制中定位切段边界的工作。保留它是为了防止中断、重开或误用素材造成混轮。原始 HDF5 保存 N 个动作和对应的 N 个动作前状态；出口 JSON 补充最后一个动作后的终态。

## 自采与复用素材的统一后处理

准备和采集完成后，依次运行：

```bash
bash memory_bench/scripts/process_recordings.sh
bash memory_bench/scripts/export_session.sh
```

| 阶段 | 自采 Key / Query | 复用 Intervent | 共同输出 |
|---|---|---|---|
| `process_recordings.sh` | 默认选每实例编号最新的完整尝试；核对 TRO、文件哈希、出口检查及转场状态继承 | 从准备阶段的 `source_inventory.json` 选择不同的候选录制，检查场景、接口、任务、边界及保护物体 | 规范化 HDF5（N 动作、N+1 状态）、相同结构的片段清单，以及 `sessions/<session_id>/segment_index.json` |
| `export_session.sh` | 从统一索引读取片段 | 从同一个统一索引读取片段 | 素材配对、物理 Bridge、完整 episode、重新渲染的 LeRobot 数据与读回检查 |

`process_recordings.sh` 顶部的 `PROCESS_OPTIONS` 可设置 `--instance-id 1`、`--attempt-id 2` 或 `--resume`。指定尝试编号需同时指定实例。只处理部分实例时索引保持未完成，不能导出整套数据。中断后用 `--resume` 核对并复用已完成产物；输入变化会报错，不覆盖已冻结结果。不完整的规范化文件需保留并换新的输出目录处理。

不需要事后切割自采长录制或源视频。最后仍会在统一世界中重新渲染完整 episode，以反映前序任务留下的物体状态和物理 Bridge。`export_session.sh` 不再隐式选择或处理 I 素材。
