# 记忆任务设计与实施要求

本文规定记忆任务的通用设计约束与验收标准。长期数据规模与完整序列约定见 [总体设计](../benchmark_design.md)。

## 1. 实现原则

**以下原则必须优先遵守，任务设计以当前代码和原生能力为基础。**

- **适配现有能力：** 使用现有交互、BDDL 条件和对象读写声明设计任务。方案不可行时，优先调整模型、尺寸、支撑物、遮挡、路线或任务规模。
- **只补充通用能力：** 允许添加必要且可复用的通用接口和函数；不得为单个任务编写处理具体操作细节的专用函数，包括专用放置区域、角度规则、状态修补或内容物固定逻辑。
- **保持真实交互：** 目标状态必须由真实物理交互产生，不能手动设置。涉及物质系统时，先核验通用系统组装与状态继承路径；不能修改状态比较、跳过系统或隐藏重置来通过验收。

## 2. 活动设计与序列

先选择有日常用途的活动，再确定历史信息如何影响 Query。遥操可达性用于筛选模型、尺寸和布局，不预先把活动限制为低处取放或收纳。

- **物体与操作多样：** 覆盖不同物体类别和交互形式，避免全部围绕物体拿放或柜体操作。
- **活动连贯：** K 与 Q 应尽量组成符合日常生活逻辑的动作序列，各片段有明确用途。
- **操作简短清晰：** K/Q 不宜过长或复杂，只保留活动目标与记忆需求所必需的步骤，不为增加动作量延长流程。
- **方便遥操：** 优先选择尺寸、重量、抓握部位和操作部位适合遥操的物体；布局应便于观察、接近和操作，避免精细对准或繁琐操作。

| 记忆类别 | 等级 | 原规划任务数 | 片段组成 |
|---|---|---|---|
| Spatial Recall（SP，空间回忆） | L1 | 2 | `1K + 2I + Q` |
| State Recall（ST，状态回忆） | L1 | 2 | `1K + 2I + Q` |
| Memory Integration（MI，记忆整合） | L2 | 2 | `2K + 2I + Q` |
| Memory Updating（MU，记忆更新） | L2 | 2 | `2K + 2I + Q` |

上表为最初四类各两项的规划。mb006 为 MU · L2：K₁ 将一根熟香肠装罐并存入吊柜，K₂ 将密封肉罐搬到另一个吊柜，Q 根据更新后的位置取出肉罐。三个吊柜覆盖六种有向换柜组合，避免从旧柜唯一推断新柜。mb007 保留 MU · L2 分组，具体记录为“随容器位置更新＋初始来源回忆”：K₂ 带内容物搬盒，Q 仍归还最初来源，不将搬运成功等同于策略必须依靠最新位置记忆。数量统计须区分这两种记忆要求。mb000–mb007 均已实现任务定义、BDDL、配置和注册；各项活动、变体与记忆要求见 [已实现任务](implemented_tasks.md)。

K 为关键片段，I 为间隔任务，Q 为目标任务；相邻片段由 Bridge（B）连接。Q 最后执行，MU 任务的 K₁ 必须先于 K₂。

每个 Key 都要有独立、真实的活动结果。不能任意切段增加 Key 数，也不能将轨迹中未发生的活动标注为已完成。

## 3. 场景与状态连续性

- **场景选择：** 在 `house_double_floor_lower`、`house_double_floor_upper`、`house_single_floor` 三个场景中选择。优先选择两个 `house_double_floor_*` 场景，并结合实际房间布局缩短片段间导航距离。
- **同房间 K/Q：** 全部 K/Q 位于同一场景、同一房间实例。
- **就近选择 I：** 两个 I 使用同场景的完整官方活动，允许跨房间。`room_id` 表示主要房间，须出现在活动绑定物体的实际房间集合中；两个 I 的主要房间互不相同，且都不是 memory room。实际涉及的其他房间可以重叠，也可以包含 memory room，但仍须满足物体与状态依赖隔离。优先选择靠近 K/Q、实际可通行路线短的活动，方便后续合成 Bridge 导航。
- **隔离 I：** I 的操作对象、容器、支撑物、物质系统及状态依赖须与 K/Q 隔离，并核对 I 之间的隔离；不能为缩短导航而放宽隔离要求。
- **固定身份：** 同一物体贯穿 K/Q，模型和尺寸固定；不能换成另一件同款物体。
- **连续世界：** 机器人按现有流程复位，物体、颗粒和容器内容连续继承，不在阶段间重置或补填。
- **资产绑定：** 允许插入同模型、同尺寸的多个独立实例，跨片段通过稳定的实例身份分别绑定，不能仅凭模型合并物体。现有流程无法区分时，应补充通用身份绑定能力，保持隔离检查，不添加任务专用处理。

## 4. 记忆有效性

| 检查项 | 要求 |
|---|---|
| 固定 Q | 同一模板的 Q 措辞不随变体改变；机器人起点和片段顺序的分配与答案独立 |
| 隐藏答案 | 内部 A/B 标签、角色绑定和答案不进入策略观测 |
| 消除当前线索 | Q 的当前观测不能直接给出历史答案；物体布局、残留状态等不得成为替代记忆的线索 |
| MI 信息独立 | 各 Key 提供独立且互补的信息，覆盖其变体组合；不能提前暴露、相互复述或通过排除法推导，Q 须联合使用这些信息 |
| MU 真实更新 | 记录旧信息、真实更新事件和最新有效信息；允许 K₂ 单独提供最新信息，不强求两个 Key 都不可缺少 |
| 搬动干扰下的来源保持 | Q 入口允许直接看见目标；不同初始来源对应相同的当前关系布局，但正确归还位置不同。落点、姿态、中转选择及残留痕迹不能揭示初始来源，不能只统一 Q 完成后的状态；K₂ 不复述来源，不强求其提供新的必要答案信息 |
| 关联变化 | 涉及物体间关系时，验证关系及其变化有真实物理依据；后续再次直接观察到目标时，明确记录为新证据 |
| I/B 无干扰 | 不改变记忆对象，不重新揭示答案；审查全部头部、双腕相机、语言、动作及 Bridge |
| 搜索与记忆分开 | 允许搜索补救的任务，分别记录首次选择正确性和最终成功，不能以最终成功替代记忆判断 |
